# SML (Stack-Map-Loglang) 表层语法与宏行为规范（宏观栈语义版）

> **设计说明**：  
> SML 放弃了传统的上下文无关文法（CFG）与显式语法树（Parse Tree），全面采用**基于栈与映射的串接式线性状态机**。  
> 语句的书写与执行顺序遵循严格的逆波兰逻辑（从右向左读取并规约：**右端为底层先发输入，左端为外层收敛指令**）。  
> 在表层语法层面，我们抽象掉底层的 λ 展开细节，将每个宏视为对**四大核心栈（QN、WT、CM、PR）、标量焦点寄存器（`⟨F⟩`）与实体属性映射（Maps）**执行确切变更的**宏观状态转移算子**。

## 1. 核心虚拟组件与数据流转拓扑

在表层语法视角下，系统的运行环境由四个核心栈、一个数字流、一个标量寄存器和八组属性映射维护：

```text
                    ┌────────────────────────┐
                    │    NM (自然数生成器)    │
                    └───────────┬────────────┘
                                │ (分配全新唯一实体 ID: x)
                                ▼
 ┌───────────────────────┐   ┌───────────────────────┐
 │    QN (量化排队栈)     │   │  WT (等待/修饰闭包栈)  │
 └───────────┬───────────┘   └───────────┬───────────┘
             │                           │ (修饰链耗尽，Rule 2b 归位)
             │                           ▼
             │               ┌───────────────────────┐
             │               │    CM (活跃成分栈)     │ <---> ⟨F⟩ (焦点寄存器)
             │               └───────────┬───────────┘
             │                           │ (动词抽取题元 / 连词消费)
             ▼                           ▼
 ┌───────────────────────────────────────────────────┐
 │        PR (排列栈) & 级联受限量化闭包 (Build !)     │
 └───────────────────────────────────────────────────┘
```

- **QN（量化排队栈，Quantifier Stack）**：维护已声明但**尚未完成受限量词闭包**的实体队列。所有实体在此排队等待被量化宏按序折叠。
- **WT（等待暂存栈，Wait Stack）**：修饰语与高阶算子的暂存区。关系宏、量词宏、模式宏驻留在 WT 形成“等待链”，接收实体并对其进行属性设置或修饰追加。
- **CM（成分栈，Component Stack）**：存放修饰完毕、可直接供谓词或连词消费的活跃实体及其**题元参与极性**，格式为 `[Polarity, Entity]`（如 `True 10` 或 `False 10`）。  
  *（注：在底层物理栈上为扁平存放的相邻两项，栈顶为实体 ID，其下方紧邻其真值极性布尔值）。*
- **PR（排列栈，Permutation Stack）**：维护置换群操作流水线（`Swap`, `Left`, `Right`, `Top`, `Bottom` 等），供复合量化宏动态改写量化顺序。
- **`⟨F⟩`（标量焦点寄存器）**：标量整数寄存器，记录当前正在执行闭包或充当定语从句核心宿主的实体标号（初始为 0）。
- **属性映射表（Maps）**：每个实体标号 `x` 绑定独立的属性集：
  - `Imap[x]`（限制域）：累积内涵修饰、属性限制与定语从句条件；
  - `Omap[x]`（核域）：累积外陈述命题；
  - `Qmap[x]`（量词类型）：记录广义量词算子（缺省为 `Exist` / ∃）；
  - `Smap[x]`（基底集合）：实体所属本体类名（如 `"猫"`, `"0~1"`, `"Ω"`）；
  - `Mmap[x]`（模式标记）：布尔值。`True` = 内模式（写入 Imap），`False` = 外模式（写入 Omap）；
  - `Fmap[x]`（焦点保护标记）：`True` = 从句受保护宿主，`False` = 普通实体；
  - `Emap`（跨句环境表）：全局键值映射，用于跨子句代词照应；
  - `Map`（词汇格框字典）：维护从集合名称到对应谓词宏代码的全局映射表。

## 2. 实体生成、修饰结合与栈间流转（核心动力学）

### 2.1 集合宏（名词/实体基底）
- **代表形式**：`S集合宏`、`农民集合宏`、`驴集合宏`、`打集合宏`...
- **宏观行为**：
  1. 向 `NM` 获取全新唯一实体编号 `x`；
  2. 初始化属性映射：`Smap[x] ← S`，`Mmap[x] ← True`（默认内模式），`Qmap[x] ← Exist`，`Imap[x] ← #`，`Omap[x] ← #`，`Fmap[x] ← False`；
  3. 将 `x` **同时压入 QN 栈与 WT 栈**；
  4. 实体进入 WT 栈后，会立即尝试与 WT 栈中先入栈的、尚未满足结合条件的宏依次结合（见 2.3）。

### 2.2 关系宏（修饰语/二元关系）
- **代表形式**：`R关系宏`、`R1关系宏`...
- **宏观行为**：
  1. 压入 WT 栈顶，自带一个布尔极性参数（默认为 `True`）；
  2. 作为一个“二元等待单元”，**必须依次结合两个实体**才开始执行具体动作：
     - **结合第 1 个实体（修饰从元 y）**：由写在其**左侧**（时序上紧随其后执行）的集合宏提供；
     - **结合第 2 个实体（被修饰主元 z）**：由继续写在其**更左侧**的主元实体提供；
  3. **注入关系式**：
     两个实体结合完成后，根据主元 `z` 的模式标记 `Mmap[z]` 决定注入位置：
     - 若 `Mmap[z] == True`（内模式），将关系式合取注入到 `Imap[z]` 中；
     - 若 `Mmap[z] == False`（外模式），将关系式合取注入到 `Omap[z]` 中；
     - 注入的关系式是否带有否定词，严格由关系宏当前的布尔极性参数决定（`True` 注入 `R(α_z, α_y)`，`False` 注入 `¬R(α_z, α_y)`）；
  4. **结合完毕释放**：将主元 `z` 放回 WT 栈顶，继续驱动后续结合。

### 2.3 WT 栈自动结合链与 CM 归位律（核心流转律）
实体在 WT 栈中与修饰单元结合并流向 CM 栈，受两条互斥规则驱动：
- **延续结合**：处于 WT 栈顶的实体 `z`，若其下方存在等待结合的单元（如尚未吸饱实体的关系宏、模式宏、量词宏），`z` 将被该单元继续结合消费。
- **自动归位 CM 栈（归位律）**：当 WT 栈上**再无任何可以结合的宏**时，触发规约规则（Rule 2b），实体 `z` 将自动脱离 WT 栈，并**以默认肯定极性 `[True, z]` 压入 CM 栈顶**。此时，该实体正式升级为可以被谓词或逻辑连接词消费的活跃论元。

## 3. 模式控制与广义量词系统（GQ Theory）

SML 原生支持蒙太格广义量词理论（Generalized Quantifier Theory），通过双轨严格切分实体的限制域与核域：

```text
Q α ∈ {α ∈ S | Imap}  Omap
```

### 3.1 模式控制宏
实体的 `Mmap` 决定了后续追加的关系是进入限制域还是核域：
- **`内模式宏`**：进入 WT 栈顶。结合一个实体 `z`，将其 `Mmap[z]` 设为 `True`（后续修饰写入 Imap）。
- **`外模式宏`**：进入 WT 栈顶。结合一个实体 `z`，将其 `Mmap[z]` 设为 `False`（后续修饰写入 Omap）。
- **`模式切换宏`**：进入 WT 栈顶。结合一个实体 `z`，将其 `Mmap[z]` 的布尔值取反（`True` ↔ `False`）。

### 3.2 量词宏（属性配置与模式自动翻转）
- **代表形式**：`存在量词宏`、`全称量词宏`、`多于一半量词宏`...
- **宏观行为**：
  进入 WT 栈顶。结合一个实体 `z` 时，原子化执行两项操作：
  1. 将实体 `z` 的量词属性修改为对应的广义量词（`Qmap[z] ← QQ`，如 `Exist`、`Forall` 或比例量词）；
  2. **自动触发一次 `模式切换宏`**，将 `Mmap[z]` 逻辑取反。
- **语用逻辑**：在自然语序中，名词先在限制域（内模式）下吸收定语；量词宏出现后，不仅赋予实体量化力，还自动将其切至外模式（核域），使得随后出现的陈述性修饰自动流入 Omap。

## 4. 谓词格框、事件本体（Ω）与定语从句穿透机制

### 4.1 名谓平权与事件本体化（Reification）
在 SML 中，动词在词法层面上与名词完全平权，同样作为集合宏声明（如 `打集合宏` 声明一个属于“打”动作概念的普通实体）。动词的二元题元格框由全局字典 `Map` 在执行期动态展开。  
一个完整的及物动词谓词执行，宏观上等价于：**纯二元谓词宏 + 事件集合宏（`Ω:S`）**。

### 4.2 纯二元谓词宏执行全景
当谓词格框被触发时，系统依次执行以下操作：
1. **生成事件变元**：声明一个全新的事件个体 `e`（`Smap[e] = Ω`），并归位至 CM 栈（格式为 `True e`）；
2. **抽取题元与释放检查（核心安全机制）**：
   从 CM 栈顶依次弹出四个论元（在物理栈上逐一弹出极性布尔值与实体 ID）：
   - 弹出第 1 项：事件本体（刚生成的 `e` 及其极性）
   - 弹出第 2 项：谓词动作概念实体（记为 `x` 及其极性）
   - 弹出第 3 项：主语实体（记为 `v` 及其极性）
   - 弹出第 4 项：宾语实体（记为 `t` 及其极性）
   
   **从句释放机制（`释放宏`）**：在弹出各个论元的同时，系统检测其 `Fmap` 属性：
   - **若某个论元的 `Fmap == True`（表明该实体是被定语从句保护的先行宿主）：系统立即将其 `Fmap` 重置为 `False`，并按顺序将其重新压回 QN 栈！**
3. **焦点锁定（`焦点宏`）**：
   读取当前 QN 栈顶的实体编号，写入标量焦点寄存器 `⟨F⟩`：
   - 若步骤 2 中有被释放回 QN 的先行词，它必然位于 QN 栈顶，`⟨F⟩` 精确锁定该先行宿主；
   - 若没有从句先行词被释放，`⟨F⟩` 默认锁定当前事件 `e`。
4. **注入题元二元关系**：
   依据各论元从 CM 栈弹出时的原始极性，将三组关系注入到对应域中（极性为 `False` 时注入带否定的关系）：  
   `宾语(e, t) ∧ 主语(e, v) ∧ 谓语(e, x)`
5. **CM 栈焦点归位**：
   谓词执行完毕后，系统将寄存器 `⟨F⟩` 所锁定的实体**以肯定极性 `[True, ⟨F⟩]` 重新压回 CM 栈顶**。
6. **题元价态（Valency）泛化**：
   上述流程以**及物动词（二元谓词）**为例，共从 CM 栈抽取 4 项（事件本体、谓词概念、主语、宾语）。若为**不及物动词**，格框宏仅抽取 3 项（事件本体、谓词概念、主语），外层收尾时配合二元排列映射宏（如 `量化映射宏_21`）；若为三元谓词（双宾语），则抽取 5 项并配合四元量化映射宏。

### 4.3 定语从句宏与先行词穿透模型
为了让先行词进入从句内部充当题元、同时防止它被从句内部的量化宏提前折叠销毁，系统通过以下流程实现“隐匿与穿透”：

```text
先行词生成 (进入 QN 与 WT)
        │
        ▼
   定语从句宏 ────────► 将先行词 Fmap 设为 True，并直接从 QN 栈顶丢弃（隐匿）
        │              （先行词仅停留在 CM 栈，等待进入从句内部）
        │
        ▼
   从句题元组装 ──────► 先行词以 CM 论元身份参与从句谓词构建
        │
        ▼
   从句谓词执行 ──────► 触发「释放宏」：检测到先行词 Fmap == True，
        │              立即将其 Fmap 复位为 False，并重新压入 QN 栈顶！
        │
        ▼
   焦点捕获与归位 ────►「焦点宏」将 QN 栈顶的先行词记录到 ⟨F⟩，
                       并将 ⟨F⟩ 以 [True, ⟨F⟩] 推回 CM 栈顶供外层使用
```

- **`定语从句宏`**：紧随先行词之后出现。它将 QN 栈顶实体的 `Fmap` 标记设为 `True`，并**强行将该实体从 QN 栈顶弹出丢弃**。这使从句内部的量化宏无法感知该实体，避免了提前闭合。
- **穿透还原**：先行词进入从句充当主语或宾语后，在谓词宏执行时被 `释放宏` 精准识别，重新入栈 QN，并由 `⟨F⟩` 护送回 CM 栈顶。先行词带着已扩充的限制域条件，完好地继续参与主句层面的推导。

## 5. 三轨正交否定体系

SML 将语言中的多义否定拆解为作用于三个物理位置的正交操作，互不干扰且无辖域漂移：

| 否定类型 | 操作宏名称 | 作用物理位置 | 宏观作用语义 |
| :--- | :--- | :--- | :--- |
| **题元角色否定** | `句内否定宏` | **CM 栈顶** | 将 CM 栈顶实体的布尔参与极性取反（`True` ↔ `False`）。用于否定该论元与谓词的题元关系（如 `¬主语`、`¬宾语`）。 |
| **局部修饰否定** | `局部否定宏` | **WT 栈顶** | 将 WT 栈顶的关系宏或形容词宏的内部布尔极性取反。用于否定具体的属性关系（如 `¬R(z, y)` 或 `¬高度度量`）。 |
| **命题全局否定** | `整体否定宏` | **QN 栈顶** | 根据 QN 栈顶实体的 Mmap，对其当前的 Imap（内模式下）或 Omap（外模式下）进行全局整体取反（`¬命题`）。 |

## 6. 量化闭包、置换流水线与量化映射宏

### 6.1 量化闭包原子操作：`Build !`
闭包的核心是由底层的 `Build !` 指令完成的二元变量折叠（Rule 16）：
- 从 QN 栈顶连续抽取两个实体：**源实体 B（待闭合变量）**与**宿主实体 A（吸收域）**；
- 将 `B` 的基底集、限制域、核域与量词类型封装为标准受限量化式：

```text
Q_B α_B ∈ {α_B ∈ S_B | Imap[B]}  (Omap[B] ∧ ...)
```

- 根据 `Mmap[A]`，将该量化式合取注入到 `A` 的 Imap 或 Omap 中，随后**完全销毁实体 B 的所有属性映射**；
- 实体 `B` 离开 QN 栈，其作用域被严格限定在宿主 `A` 的辖域内。

### 6.2 置换后缀原理与偏移补偿机制（Shifted Permutation）
在 `量化宏_321` 或 `量化映射宏_321` 中，后缀数字（如 `321`）具有严密的表层与底层对应逻辑：

1. **表层直观理解**：  
   表层排列元组 `(i_k, ..., i_1)` 表示对 QN 栈中**除去栈顶元素之后的第 k 个、...、第 1 个论元变量**进行顺序重排；
2. **底层偏移机制（`Bottom` 变换）**：  
   在宏执行时，系统会自动调用 `Bottom` 指令（Rule 29）对表层元组施加变换：

```text
Bottom(i_k, ..., i_1) = (1+i_k, ..., 1+i_1, 1)
```

   - 底层追加的末位 `1`，确保**刚刚生成的宿主实体（如事件 e）牢固锁定在 QN 栈顶（第 1 位）**；
   - 其余各论元的位置统一加 1。因此，表层的 `(3, 2, 1)` 在实际执行时精确作用于底层的 `(4, 3, 2, 1)`，分别对应 QN 栈上的三个待折叠题元与一个宿主事件；
3. **级联计数闭包**：  
   后缀中元素的个数对应计数嵌套列表的深度（如 `321` 对应 `[[[[]]]]`，深度为 3）。它驱动系统连续执行 3 次 `Build !`，将重排后的 3 个论元依次闭合进宿主事件中。

### 6.3 `量化宏` vs `量化映射宏`
- **`量化宏`（驻留 WT 栈）**：
  进入 WT 栈顶，结合一个实体后，直接对 QN 栈上的论元应用预设的排列与连续 `Build !` 闭包（常用于名词短语内部的局部量化折叠）。
- **`量化映射宏`（作用于 CM 栈顶，中央总线算子）**：
  直接针对当前位于 CM 栈顶的动词谓词实体触发：
  1. **展开动词格框**：查阅全局字典 `Map`（Rule 17），执行该动词对应的谓词宏（声明事件 Ω、装配题元）；
  2. **消费 PR 栈流水线**：若 PR 栈中预存了置换调整指令（如 `副作用顶排列宏`、`交换排列宏`），量化映射宏在执行闭包前**优先消耗 PR 栈中的指令，动态修改默认的置换元组与计数深度**；
  3. **级联量化闭包**：应用最终确定的置换元组，执行连续的 `Build !`，完成整句的论元闭合。

## 7. 跨子句照应、因果/逻辑连接词与驴子句

### 7.1 跨子句代词照应（Upload / Download）
为了在无语法树的线性语流中实现精确的跨子句代词指称，系统通过 `Emap` 维护动态环境：
- **`上传宏 [alias]`**：读取当前 **CM 栈顶**实体的编号，在 `Emap` 中将其与别名绑定；
- **`肯定下载宏 [alias]`**：从 `Emap` 提取该实体编号，以肯定极性 `[True, ID]` 压入 CM 栈顶；
- **`否定下载宏 [alias]`**：从 `Emap` 提取该实体编号，以否定极性 `[False, ID]` 压入 CM 栈顶。

### 7.2 逻辑与因果连接词宏
- **`顺连接词宏` / `逆连接词宏`**：
  从 CM 栈获取两个已完成局部闭合的子事件，声明连接总事件 Ω，写入连接词前件与后件关系，并**自动对两个子事件触发内部的 `Build !` 闭包**。
- **`裸连接词宏` 与延时闭包**：
  **彻底剔除了内部自带的 `Build !` 闭包逻辑**。它仅仅在总事件与两个子事件之间建立前件/后件关系，将量化闭包的控制权完全移交给外层量化宏。

### 7.3 驴子句（Donkey Sentences）消解机制
面对“如果每个农民有一头驴，他就打这头驴”这一经典难题，若在从句内部提前将“驴”进行存在闭合，后半句代词将无法获得绑定。SML 通过 **`裸连接词宏` + 外层量化** 解决此问题：
1. **条件句生成**：在生成“驴”和“农民”时通过 `上传宏` 登记别名；
2. **结论句引用**：在后半句通过 `肯定下载宏` 跨句复用这两个实体装配“打”事件；
3. **`裸连接词宏` 挂接**：将“有事件”与“打事件”挂接为总事件的前件与后件，**但不触发内部量化折叠**；
4. **外层统一闭包**：由于实体未被提前销毁，外层的全称量词宏能够穿透到最外层，将全句中的共变变量一次性完成全称受限量化闭合。

## 8. 标度语义学（形容词与副词模型）

SML 将形容词与副词规范化为作用于连续标度区间上的二元测度关系：

### 8.1 形容词宏（复合标度测度单元）
- **代表形式**：`高的宏`、`重的宏`...
- **宏观行为**：
  形容词宏在宏观上可视为一个预封装的度量单元（包含度量集合 `0~1:S` 与二元度量关系 `高度度量:R`）。  
  当它与靶实体结合时，在内部生成标度变量 `d ∈ 0~1`，建立度量关系，并通过内部自闭合机制将标度变量局部折叠进靶实体的域中。  
  **自闭合特性（Self-closing）**：与普通的 `R关系宏` 不同，形容词宏底层代码内部自带了 `Build !` 指令。与宿主主元结合后，会在局部就地将度量标尺变量折叠闭合进宿主域内，因此外部**无需额外追加量化宏**对其进行闭合。

### 8.2 副词宏（标度调节算子）
副词宏直接作用于 WT 栈上的标度度量单元：
- **`量化副词宏`（如 `全称副词宏`）**：修改标度变量的量词类型（如改为 ∀），用于表达极限程度（如“极重”表现为对该标度区间的全称覆盖）；
- **`副词宏`（如 `副词1宏`）**：调用 `Transform` 算子对标度区间集合施加函数变换（如平移或放缩区间）；
- **配合 `局部否定宏`**：直接反转 WT 栈中度量关系的极性，表达“不高/不重”等属性否定。
