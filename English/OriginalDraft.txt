The data structure consists of six stacks, one number stream, one scalar register, and eight associative maps.

The six stacks and one number stream are defined as follows (all operate as LIFO stacks where the right end is the top):
1. Input Stack (IP): Instruction queue holding tokens, code blocks, and unpacked macros awaiting reduction.
2. Number Stream (NM): Infinite generator stream of monotonically increasing natural numbers: 1 2 3 ...
3. Quantifier Queue (QN): Entity argument queue awaiting generalized quantifier closure.
4. Wait Stack (WT): Staging area for higher-order continuation closures, intermediate entities, and modifier polarities.
5. Component Stack (CM): Storage for active argument entities and their truth polarity cursors (formatted as Polarity Entity).
6. Permutation Stack (PR): Pipeline stack for permutation group operations and dynamic combinator adjustments.
7. Output Stack (OP): Immediate evaluation and reduction workspace for atomic operations, boolean logic, and relational links.

One scalar register:
- Focus Register (<F>): Scalar integer (initially 0), recording the ID of the core host entity currently undergoing relative clause closure.

The eight associative maps:
1. Restrictor Map (Imap): Accumulates nominal restrictions and relative clause formulas inside {α_i ∈ S_i | Imap[i]}.
2. Nuclear Scope Map (Omap): Accumulates external matrix predicate assertions.
3. Quantifier Map (Qmap): Maps an entity to its quantifier force (default: Exist).
4. Set Map (Smap): Maps an entity ID to its base set category name (e.g., "Cat", "Ω").
5. Mode Map (Mmap): Boolean routing mode (True = Inner mode, writes to Imap; False = Outer mode, writes to Omap).
6. Focus Flag Map (Fmap): Boolean flag (True = protected relative clause host, False = regular argument).
7. Environment Map (Emap): Dynamic variable alias mapping for cross-clause pronoun coreference.
8. Lexical Macro Map (Map): Global dictionary mapping set name strings to their corresponding predicate frame macro tokens.

The keys for all entity-related maps are entity integer IDs.

Notational Conventions:
- Lowercase letters represent variables or arbitrary elements.
- Uppercase letters represent arbitrary elements or specific syntactic categories.
- "A:N" denotes an entity integer ID.
- "A:S" denotes a set word.
- "A:R" denotes a binary relation word.
- "A:QQ" denotes a quantifier functor word.
- "A:SS" denotes a base set transformation word.
- "A:B" denotes a boolean value (True or False).
- "Ω" denotes the event domain universe.
- "#" denotes the identity empty expression (# ∧ A = A, A ∧ # = A, # ∧ # = #).
- "!" denotes the execution trigger operator.
- "[..., A]" denotes that the top (rightmost) element of the list is A.
- "??" denotes any matching stack or map identifier.
- "∇" denotes state-machine side-effect operations during transition.
- "-" denotes nothing / no-op (the target stack or map remains unchanged).
- Stacks and maps not explicitly mentioned in a rule remain unchanged by default.

Execution Lifecycle:
1. User input tokens are pushed to IP.
2. Match Start Rules once (matching top to bottom).
3. Loop match Loop Rules repeatedly until reaching a fixed point (matching top to bottom).
4. Repeat from Step 2 until IP is empty.
