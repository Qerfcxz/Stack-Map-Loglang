<Surface Syntax and Macro Specifications>

[Core Reading Notice]
All syntactic constructions and instruction sequences in this document are strictly written according to the "Parser Input Order".
Because the underlying abstract machine executes via concatenative reverse evaluation (LIFO pop order), the text sequence order fed into the parser is the exact reverse of human natural language surface order:
The rightmost token in the sequence is read and evaluated first; the leftmost token is read and closed last.
Therefore, all descriptions in this specification follow this convention:
- "Left": instructions written earlier in the text (evaluated later / outer wrapping scope).
- "Right": instructions written later in the text (evaluated earlier / inner core).

================================================================================
Part 1: Surface Syntax System and Sentence Construction
================================================================================

I. Basic Matrix Sentence Construction
A basic proposition concludes with a quantifier mapping macro, with predicate, subject, and object arranged sequentially to its right.

Basic Structure:
[Quant_Mapping_Macro_{Perm}] [Predicate_Set_Macro] [Subject_Set_Macro] [Object_Set_Macro]

Description:
1. The object macro at the far right executes first, generating the object entity; the subject executes next; the predicate executes last.
2. The final Quant_Mapping_Macro unpacks the verbal predicate frame and assembles the subject, predicate, and object into a closed event proposition.
3. The permutation tuple suffix in the macro name (e.g., 321, 123, etc.) dictates the relative quantifier scoping hierarchy among predicate, subject, and object.
4. For intransitive or ternary predicates, simply adjust the number of argument set macros and select the corresponding arity of Quant_Mapping_Macro.

II. Single Binary Modification
Binary relational modifiers restrict a core entity or event. The modification block is uniformly placed to the left of the modified set macro.

Basic Structure:
[Quant_Mapping_Macro_321] [Mod_Set_Macro] [Mod_Rel_Macro] [Quant_Macro_1] [Predicate_Set_Macro] [Subject_Set_Macro] [Object_Set_Macro]

Description:
1. [Mod_Set_Macro] [Mod_Rel_Macro] [Quant_Macro_1] forms a complete modification unit situated to the left of the Predicate_Set_Macro, modifying the matrix event of the clause.
2. [Quant_Macro_1] binds and closes the modifier entity into the matrix event.
3. If this local quantifier macro is omitted, the arity of the leftmost Quant_Mapping_Macro must be increased to close the entity during matrix resolution.

III. Coordinate Modifications and Batch Closure
A single host entity can simultaneously attach multiple independent modification relations and close them in a batch using a higher-arity quantifier macro.

Basic Structure:
[Quant_Mapping_Macro_321] [Mod_Set_Macro1] [Mod_Rel_Macro1] [Mod_Set_Macro2] [Mod_Rel_Macro2] [Quant_Macro_21] [Predicate_Set_Macro] [Subject_Set_Macro] [Object_Set_Macro]

Description:
1. Mod_Set1 via Rel1, and Mod_Set2 via Rel2, coordinately modify the matrix event.
2. Because two modifier entities are accumulated on the queue, [Quant_Macro_21] is placed to their left to execute a dual closure.
3. The count of indices in the permutation tuple must strictly match the number of attached modifier entities.

IV. Nested Modification
A modifier entity is itself a unary set entity and can serve as a host for further modifications to its left, extending arbitrary branches of a Directed Acyclic Graph (DAG).

Basic Structure:
[Quant_Mapping_Macro_321] [Mod_Set_Macro1] [Sub_Mod_Set_Macro] [Sub_Mod_Rel_Macro] [Quant_Macro_1] [Mod_Rel_Macro1] [Mod_Set_Macro2] [Mod_Rel_Macro2] [Quant_Macro_21] [Predicate_Set_Macro] [Subject_Set_Macro] [Object_Set_Macro]

Description:
1. [Sub_Mod_Set_Macro] [Sub_Mod_Rel_Macro] [Quant_Macro_1] strictly and uniquely modifies [Mod_Set_Macro1], forming a local intensional restriction.
2. The restricted entity is then attached to the matrix predicate via [Mod_Rel_Macro1] alongside Modifier 2.

V. Independent Constituent Modification
All modification patterns described above can be attached homomorphically to subjects, objects, or any base category, not merely to the verbal predicate event.

Basic Structure:
[Quant_Mapping_Macro_321] [Predicate_Set_Macro] [Subject_Set_Macro] [Mod_Set_Macro] [Mod_Rel_Macro] [Quant_Macro_1] [Object_Set_Macro]

Description:
The modification unit immediately borders the left of Object_Set_Macro, strictly modifying the object without scope leakage into the subject or predicate.

VI. Generalized Restricted Quantifiers and Mode Partitioning
All relational modifications write to the entity's restrictor map (Imap) by default. Inserting a quantifier macro toggles the mode, partitioning subsequent relations into the nuclear scope map (Omap).

Basic Structure:
[Quant_Mapping_Macro_321] [Mod_Set_Macro1] [Mod_Rel_Macro1] [Forall_Quant_Macro] [Mod_Set_Macro2] [Mod_Rel_Macro2] [Quant_Macro_21] [Predicate_Set_Macro] [Subject_Set_Macro] [Object_Set_Macro]

Description:
1. Modifier 2 on the right writes to Inner Mode (Imap), defining the domain restriction of the entity.
2. [Forall_Quant_Macro] flips the mode boolean to False and assigns universal quantifier force to the entity.
3. Modifier 1 on the left writes to Outer Mode (Omap), expressing the asserted predicate content.
4. This realizes the strict separation between restrictor and nuclear scope mandated by Generalized Quantifier (GQ) theory.

VII. Relative Clause Mechanism
Relative clauses operate on entity variables on the quantifier queue. The clause body is placed directly to the left of the host set macro and anchored via Rel_Clause_Macro.

Basic Structure:
[Matrix_Quant_Mapping_Macro] [Matrix_Predicate] [Clause_Quant_Mapping_Macro] [Clause_Predicate] [Clause_Subject] [Rel_Clause_Macro] [Host_Noun_Macro]

Description:
1. The host noun is placed immediately to the right of [Rel_Clause_Macro]. Upon creation, it is flagged as a protected focus and removed from QN.
2. The complete clause structure unfolds to the left of [Rel_Clause_Macro]. The clause predicate automatically captures the focus host during reduction.
3. Once the clause closes, the host entity is safely restored in situ to QN and CM, participating as an ordinary argument in the outer matrix clause.

VIII. Order-Insensitivity of Local Modification Clusters
For modification macros that operate on the wait stack (WT) or mutate unary attributes (mode, quantifier force, polarity), their order within the same modification cluster is commutative.
For example, when restricting an adjective or relation:
[Local_Neg_Macro] [Forall_Adv_Macro] [Adj_Macro]
and
[Forall_Adv_Macro] [Local_Neg_Macro] [Adj_Macro]
are completely equivalent in their evaluated logical formula. They perform aspectual modifications on the continuation closure on WT without altering the topological consumption sequence.

IX. Cross-Clause Pronoun Coreference (Anaphora)
Coreference is achieved via the environment map (Emap) for multi-clause discourse and classic donkey sentences.

Basic Structure:
[Total_Closure_Macro] [Connective_Macro] [Matrix_Predicate] [Pos_Download_Macro y] ... [Clause_Predicate] [Upload_Macro y] [Clause_Entity] ...

Description:
1. In the subordinate clause, [Upload_Macro alias] is placed to the left of the entity, registering the entity ID into Emap under the specified alias.
2. In subsequent clauses, [Pos_Download_Macro alias] directly replaces the position where an argument set macro would normally sit.
3. Coupled with bare connective macros that delay quantification, coreferent arguments are bound simultaneously at the outermost matrix level.

================================================================================
Part 3: Functional Descriptions and Positioning Reference for Direct-Use Macros
================================================================================

This section lists macros that can be directly invoked without arguments, detailing their semantics and sentence positions.

--------------------------------------------------------------------------------
1. Negation Macros
--------------------------------------------------------------------------------

(1) Global_Neg_Macro
Function: Propositional global negation. Applies logical NOT over the outermost closed matrix proposition.
Position: Placed at the far left of the entire proposition to be negated (evaluated last by the parser).
Canonical Pattern: Global_Neg_Macro [Quant_Mapping_Macro_xxx] [Predicate...]

(2) Constituent_Neg_Macro
Function: Thematic constituent negation. Inverts the component stack cursor polarity, precisely negating the role relation between an argument and the predicate.
Position: Placed immediately to the left of the negated argument set macro.
Canonical Pattern: [Matrix_Predicate...] Constituent_Neg_Macro [Object_Set_Macro]
Semantics: In the current event, the argument does not assume the corresponding thematic role (e.g., "is not the object").

(3) Local_Neg_Macro
Function: Relation or adjective negation. Directly flips the polarity of the continuation closure on the wait stack.
Position: Placed immediately to the left of the negated relation macro or adjective macro.
Canonical Pattern: [Mod_Set] Local_Neg_Macro [Rel_Macro]
Canonical Pattern: Local_Neg_Macro [Adj_Macro]

--------------------------------------------------------------------------------
2. Clause Control Macros
--------------------------------------------------------------------------------

(1) Rel_Clause_Macro
Function: Anchors the relative clause host. Blocks immediate closure and flags the host as protected under the focus register.
Position: Placed immediately to the left of the host noun macro; the clause body continues to its left.
Canonical Pattern: [Clause_Quant_Mapping_Macro] [Clause_Internal_Structure...] Rel_Clause_Macro [Host_Noun_Macro]

(2) Release_Macro
Function: Inspects the entity's focus flag; if it is a protected host, safely returns it to QN and clears the flag.
Position: Encapsulated internally within composite templates like Binary_Pred_Macro, automatically executed when arguments are popped.

(3) Focus_Macro
Function: Extracts the current top entity from QN and registers it into the focus register <F>.
Position: Encapsulated internally within predicate frame macros; not written manually by users.

--------------------------------------------------------------------------------
3. Quantifier and Mode Control Macros
--------------------------------------------------------------------------------

(1) Exist_Quant_Macro
Function: Sets the entity's quantifier force to existential (∃) and toggles the mode.
Position: Placed in the entity's modification chain between the inner-mode block and outer-mode block.
Canonical Pattern: [Nuclear_Scope_Block] Exist_Quant_Macro [Restrictor_Block] [Quant_Macro] [Set_Macro]

(2) Forall_Quant_Macro
Function: Sets the entity's quantifier force to universal (∀) and toggles the mode.
Position: Placed between the two modification blocks of the restricted entity.
Canonical Pattern: [Nuclear_Scope_Block] Forall_Quant_Macro [Restrictor_Block] [Quant_Macro] [Set_Macro]

(3) MoreThanHalf_Quant_Macro
Function: Sets the entity's quantifier force to a proportional generalized quantifier ("More Than Half") and toggles the mode.
Position: Same as above; used for proportional quantifier propositions.

(4) Inner_Mode_Macro / Outer_Mode_Macro
Function: Forces subsequent relations to explicitly write into Imap (restrictor) or Omap (nuclear scope).
Position: Placed to the left of a relation macro or modification block.

(5) Mode_Toggle_Macro
Function: Flips the entity's mode boolean in place.
Position: Embedded as an atomic step inside quantifier macros; rarely invoked directly.

--------------------------------------------------------------------------------
4. Environment and Coreference Macros
--------------------------------------------------------------------------------

(1) Upload_Macro
Function: Captures the newly generated entity ID and registers it in Emap under the specified alias.
Position: Placed immediately to the left of the entity set macro, followed by the alias identifier.
Canonical Pattern: Upload_Macro alias [Set_Macro]

(2) Pos_Download_Macro
Function: Retrieves an entity ID from Emap, pushes it to CM, and assigns positive truth polarity (True).
Position: Replaces the position where the argument set macro would normally be written.
Canonical Pattern: [Matrix_Predicate...] Pos_Download_Macro alias

(3) Neg_Download_Macro
Function: Retrieves an entity ID from Emap, pushes it to CM, and assigns negative truth polarity (False).
Position: Replaces the position where the argument set macro would normally be written.

--------------------------------------------------------------------------------
5. Adverbial and Degree Modification Macros
--------------------------------------------------------------------------------

(1) Forall_Adv_Macro / Exist_Adv_Macro / MoreThanHalf_Adv_Macro
Function: Quantifies over the normalized scale interval (0~1) upon which an adjective depends.
Position: Placed to the left of the adjective macro.
Canonical Pattern: Forall_Adv_Macro [Heavy_Macro]

(2) Opposite_Macro
Function: Inverts the polarity/direction of the scale metric of an adjective.
Position: Placed to the left of the adjective macro.
Canonical Pattern: Opposite_Macro [Tall_Macro]

--------------------------------------------------------------------------------
6. Permutation Pipeline Control Macros
--------------------------------------------------------------------------------

(1) Swap_Perm_Macro / Left_Perm_Macro / Right_Perm_Macro / Top_Perm_Macro / Bottom_Perm_Macro
Function: Performs side-effect-free algebraic transformations on the permutation tuple on PR (swapping, circular shifting, etc.).
Position: Placed to the left of Quant_Mapping_Macro, participating in pipeline traversal.

(2) SideEffect_Top_Perm_Macro / SideEffect_Bottom_Perm_Macro
Function: Pushes stateful permutation operations onto PR, dynamically mutating the tuple and expanding the Peano counter level during traversal.
Position: Placed to the left of clauses requiring dynamic intervention in quantifier scoping order.
Canonical Pattern: [Quant_Mapping_Macro_xxx] SideEffect_Bottom_Perm_Macro [Clause_Body...]

--------------------------------------------------------------------------------
7. Logical Connective Macros
--------------------------------------------------------------------------------

(1) Forward_Causal_Macro (Instantiation of Forward Connective Macro)
Function: Connects two event propositions according to forward causality (cause precedes effect) and closes them.
Position: Placed at the far left of the two connected clauses.
Canonical Pattern: Forward_Causal_Macro [Consequent_Clause_Proposition] [Antecedent_Clause_Proposition]

(2) Reverse_Causal_Macro (Instantiation of Reverse Connective Macro)
Function: Connects two event propositions according to reverse causality (effect precedes cause) and closes them.
Position: Placed at the far left of the two connected clauses.
Canonical Pattern: Reverse_Causal_Macro [Antecedent_Clause_Proposition] [Consequent_Clause_Proposition]

(3) Bare_Causal_Macro (Instantiation of Bare Connective Macro)
Function: Establishes causal thematic edges without immediately closing argument quantifiers internally, preserving variables for cross-clause anaphora.
Position: Used in donkey sentences, placed to the right of a higher-arity quantifier mapping macro and to the left of the two clauses.
Canonical Pattern: [Quant_Mapping_Macro_4321] Bare_Causal_Macro [Consequent_Clause...] [Antecedent_Clause...]
